1.首先添加大量调试输出（DBG: xxx），定位崩溃的具体位置。
2.对比 mock 数据与真实 API：发现 mock 数据测试成功，真实 API 测试失败，初步判断是数据解析或网络返回数据的内存生命周期有问题。
3.优化 cJSON 解析逻辑：弃用旧代码在新 API 格式下的 cJSON_Duplicate（容易导致内存问题），

4.解决网络回调的生命周期：在 HTTP 响应的回调函数中添加 strdup 深拷贝数据，避免 HTTP 底层机制将 response 提前释放引发的数据踩踏。
5.解决多线程 UI 崩溃（核心步骤）：排查发现底层 HTTP 请求是运行在子线程中的，而 LVGL 不是线程安全的。
   子线程直接调用 UI 创建/销毁逻辑导致了链表错乱。采取的解决办法是引入 lv_async_call，
   将拷贝好的 JSON 字符串推送到主线程去安全调度渲染 UI。
6.解决野指针与乱码问题（核心步骤）：排查乱码原因发现，当点击搜索按钮后，
   页面调用了 lv_obj_clean 销毁了输入框，导致原来获取到的 keyword 指针指向了被释放的内存区。
   后续网络模块再去读取时读到了复用的 UI 二进制数据，造成乱码和崩溃。
   解决办法：在销毁界面前，先用 strdup 把搜索词拷贝到安全内存，传递给 list 界面后再 free。

search 界面只负责“输入并跳转”。增加了 cleanup_before_exit() 彻底清理挂载在最顶层 (lv_layer_top)
