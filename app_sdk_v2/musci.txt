一、项目背景与需求分析
================================================================================

1.1 现有基础
--------------------------------------------------------------------------------
硬件平台:
  - T113开发板(自制四层PCB，手动焊接)
  - FL7707触摸屏控制器，分辨率1440x280
  - WiFi模块(已实现网络连接)
  - BLE Mesh蓝牙模块
  - 音频输出硬件

软件基础:
  - LVGL图形库(已集成)
  - curl库实现HTTP请求
  - cJSON库实现JSON解析
  - 多线程/多进程架构
  - 消息队列通信机制(osal_queue)
  - 异步音频播放框架(audio_player_async)
  - CMake编译系统
  - SSH连接虚拟机，ADB Shell连接硬件

已实现功能:
  - 网络时间同步
  - 天气信息获取
  - 城市设置
  - 闹钟功能
  - 番茄时钟
  - 屏幕亮度调节
  - 音量调节
  - WiFi设置

1.2 新增功能需求
--------------------------------------------------------------------------------
目标: 开发一个类似QQ音乐的在线音乐播放器

核心功能:
  1. 在线音乐搜索 - 通过关键词搜索歌曲
  2. 歌曲列表展示 - 显示搜索结果列表
  3. 在线音乐播放 - 流媒体播放网络音乐
  4. 播放控制 - 播放/暂停/上一首/下一首
  5. 进度控制 - 播放进度条拖动
  6. 音量控制 - 音量调节滑块
  7. 播放模式 - 顺序播放/随机播放/单曲循环
  8. 歌词显示 - 同步显示歌词(可选)
  9. 收藏列表 - 本地收藏歌曲(可选)
  10. 历史记录 - 播放历史(可选)

2.3 音乐API选择
--------------------------------------------------------------------------------
推荐使用免费音乐API(需自行调研选择):

方案一: 网易云音乐API (非官方)
  - 搜索接口: /search?keywords=xxx
  - 歌曲详情: /song/detail?ids=xxx
  - 歌曲URL: /song/url?id=xxx
  - 歌词接口: /lyric?id=xxx

方案二: 酷狗音乐API (非官方)
  - 搜索接口: /search?keyword=xxx
  - 播放地址: /play?hash=xxx

方案三: 自建音乐服务器
  - 搭建简单的音乐代理服务器
  - 完全可控，无API限制

// 歌曲信息
typedef struct {
    int id;                     // 歌曲ID
    char name[128];             // 歌曲名
    char artist[128];           // 歌手名
    char album[128];            // 专辑名
    char pic_url[512];          // 封面图片URL
    char play_url[512];         // 播放地址URL
    int duration;               // 时长(毫秒)
    char lyric[4096];           // 歌词
} music_info_t;

// 播放列表
typedef struct {
    music_info_t *songs;        // 歌曲数组
    int count;                  // 歌曲数量
    int capacity;               // 数组容量
} music_list_t;

// 播放状态
typedef struct {
    int current_index;          // 当前播放索引
    int play_mode;              // 播放模式(0顺序/1随机/2单曲)
    int is_playing;             // 是否正在播放
    int current_position;       // 当前播放位置
    int volume;                 // 当前音量
} play_state_t;

// 播放模式枚举
typedef enum {
    PLAY_MODE_SEQUENCE = 0,     // 顺序播放
    PLAY_MODE_RANDOM,           // 随机播放
    PLAY_MODE_SINGLE_LOOP,      // 单曲循环
} play_mode_e;

六、注意事项与风险
================================================================================

6.1 技术风险
--------------------------------------------------------------------------------
1. 音乐API稳定性
   - 风险: 免费API可能不稳定或被封禁
   - 对策: 准备多个API备选方案，或自建代理服务器

2. 网络流媒体播放
   - 风险: T113性能可能不足以流畅播放高码率音频
   - 对策: 选择低码率音频源，优化缓冲策略

3. 内存限制
   - 风险: 嵌入式设备内存有限，可能内存不足
   - 对策: 优化内存使用，及时释放资源

4. 音频解码
   - 风险: 需要合适的音频解码库支持
   - 对策: 使用成熟的命令行播放器(madplay/mpg123)

6.2 开发注意事项
--------------------------------------------------------------------------------
1. 代码规范
   - 遵循现有代码风格
   - 添加必要的注释
   - 使用有意义的变量名

2. 错误处理
   - 网络请求失败处理
   - 音频播放错误处理
   - 内存分配失败处理

3. 资源管理
   - 及时释放内存
   - 关闭文件描述符
   - 清理线程资源

4. 线程安全
   - 使用消息队列通信
   - 避免全局变量竞争
   - 注意回调函数的线程上下文

6.3 性能优化建议
--------------------------------------------------------------------------------
1. UI优化
   - 避免频繁刷新
   - 使用局部刷新
   - 合理使用动画

2. 网络优化
   - 实现请求缓存
   - 使用连接池
   - 压缩传输数据

3. 内存优化
   - 及时释放资源
   - 避免内存碎片
   - 使用内存池
